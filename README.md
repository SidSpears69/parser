# Web Parser

## Запуск

Команды PowerShell из каталога проекта:

```powershell
py -3.14 -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
.\.venv\Scripts\python.exe -m playwright install firefox
.\.venv\Scripts\python.exe main.py
```

Активация виртуального окружения не требуется. Установка PySide6 включает Qt:
[официальная инструкция](https://doc.qt.io/qtforpython-6.10/gettingstarted.html).
После установки можно запускать приложение двойным щелчком по `start.cmd`.

## Проверка интерфейса

```powershell
.\.venv\Scripts\python.exe -m unittest discover -s tests -v
```

## Прокси

В «Общих настройках» можно заполнить до трёх прокси. Пустые слоты пропускаются. Укажите адрес с протоколом (`http://host:port` или `socks5://host:port`) и при необходимости заполните поля логина и пароля.

Парсер запоминает успешный маршрут отдельно для Ozon, Wildberries и Яндекс Маркета и использует его первым для следующих товаров и обходов, пока приложение открыто. При сбое соединения с прокси парсер может попробовать другой маршрут из пула.

## Капча Яндекс Маркета

Для автоматического решения координатной Yandex SmartCaptcha можно подключить платный сервис [2Captcha](https://2captcha.com/ru/api-docs/yandex-smart-captcha). Получите ключ API и задайте его в PowerShell перед запуском приложения:

```powershell
$env:WEB_PARSER_2CAPTCHA_API_KEY = "ваш-ключ-api"
.\.venv\Scripts\python.exe main.py
```

Переменная действует только в этом окне PowerShell; для установленного приложения его также нужно запускать из окна с заданной переменной. Изображения задания и инструкции отправляются в 2Captcha для распознавания, за запросы может взиматься плата. Пароли и cookies браузера сервису не передаются. Поддерживаются координатные задания; другие виды проверок могут остаться нерешёнными. Доступность и актуальность разметки зависят от Яндекса и сервиса.

Если ключ не задан или капча не решена, парсер записывает в журнал ID товара и URL. Следующие ссылки Маркета проверяются на том же маршруте. Поскольку обход неполный, парсер сохраняет предыдущую выгрузку на FTP.

Для SOCKS5 с авторизацией приложение поднимает временный локальный переходник на `127.0.0.1`, поскольку Playwright не передаёт SOCKS5-учётные данные браузеру. Переходник работает только во время сеанса браузера.

## Почтовые уведомления

На верхнем уровне приложения откройте «Общие настройки». Внутри находятся загрузка и сохранение конфигурации, прокси и почтовые уведомления; четыре вкладки сайтов остались в разделе «Сайты». В секции «Уведомления по почте» укажите SMTP-сервер без протокола, порт и режим SSL/TLS или STARTTLS. Укажите логин, пароль SMTP, адрес отправителя и один или два разных адреса получателей. Если SMTP-сервер разрешает отправку без авторизации, оставьте логин и пароль пустыми. Настройки всех вкладок автоматически сохраняются в `%LOCALAPPDATA%\WebParser\settings.json` и загружаются при следующем запуске, в том числе после обновления приложения. Кнопки «Загрузить…» и «Сохранить…» служат для импорта и экспорта файла вручную. Если настройки сохранены только в старом файле, загрузите его один раз через «Загрузить…». Секреты шифруются средствами Windows DPAPI и доступны той же учётной записи Windows.

Включите отправку и нажмите «Отправить тест»: письмо уйдёт на оба указанных адреса. Приложение отправляет предупреждения о запасных селекторах, ошибки из журнала и сообщение об аварийной остановке. Отправка идёт в фоне; результат проверки и ошибки SMTP показываются в этой же секции. Серверу Windows нужен сетевой доступ к указанному SMTP-хосту и порту.

## Обновления

После публикации релиза workflow обновляет `update.json` в отдельной ветке `release-feed`. Кнопка проверки обновлений читает этот небольшой файл через `raw.githubusercontent.com`; если он недоступен, использует файл релиза на GitHub. Установщик по-прежнему проверяется по размеру и SHA-256. Для уже установленной версии, которая получает HTTP 403, новую версию можно один раз скачать вручную со страницы релизов; затем проверка по кнопке будет использовать новый основной источник.
