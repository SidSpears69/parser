# Web Parser

## Запуск

Команды PowerShell из каталога проекта:

```powershell
py -3.14 -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
.\.venv\Scripts\python.exe -m playwright install firefox
.\.venv\Scripts\python.exe main.py
```

Активация виртуального окружения не требуется. Установка PySide6 включает Qt:
[официальная инструкция](https://doc.qt.io/qtforpython-6.10/gettingstarted.html).
После установки можно запускать приложение двойным щелчком по `start.cmd`.

## Проверка интерфейса

```powershell
.\.venv\Scripts\python.exe -m unittest discover -s tests -v
```

## Прокси

Включите общий прокси в приложении и укажите адрес с протоколом, например `http://host:port` или `socks5://host:port`; логин и пароль задаются отдельно. Для SOCKS5 с авторизацией приложение поднимает временный локальный переходник на `127.0.0.1`, поскольку Playwright не передаёт SOCKS5-учётные данные браузеру. Переходник работает только во время сеанса браузера.

## Почтовые уведомления

На верхнем уровне приложения откройте «Общие настройки». Внутри находятся загрузка и сохранение конфигурации, прокси и почтовые уведомления; четыре вкладки сайтов остались в разделе «Сайты». В секции «Уведомления по почте» укажите SMTP-сервер без протокола, порт и режим SSL/TLS или STARTTLS. Укажите логин, пароль SMTP, адрес отправителя и один или два разных адреса получателей. Если SMTP-сервер разрешает отправку без авторизации, оставьте логин и пароль пустыми. При сохранении общей конфигурации пароль шифруется средствами Windows DPAPI.

Включите отправку и нажмите «Отправить тест»: письмо уйдёт на оба указанных адреса. Приложение отправляет предупреждения о запасных селекторах, ошибки из журнала и сообщение об аварийной остановке. Отправка идёт в фоне; результат проверки и ошибки SMTP показываются в этой же секции. Серверу Windows нужен сетевой доступ к указанному SMTP-хосту и порту.

## Обновления

После публикации релиза workflow обновляет `update.json` в отдельной ветке `release-feed`. Кнопка проверки обновлений читает этот небольшой файл через `raw.githubusercontent.com`; если он недоступен, использует файл релиза на GitHub. Установщик по-прежнему проверяется по размеру и SHA-256. Для уже установленной версии, которая получает HTTP 403, новую версию можно один раз скачать вручную со страницы релизов; затем проверка по кнопке будет использовать новый основной источник.
